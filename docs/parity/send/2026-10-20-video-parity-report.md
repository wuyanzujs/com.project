## 二、验证方法

1. **生产端真机取证**：真机安装生产包后用 `adb screencap` 截图、`adb shell uiautomator dump` 取控件 bounds（Flutter 语义树可用），再用 PIL 做像素级量测（颜色、边界、圆角、行高）。所有坐标与颜色均可复算。
2. **生产端包内取证**：从 `libapp.so`（Dart AOT，字符串以 UTF-16LE 存储）中检索 UI 文案与类名，作为「页面/字段确实存在于生产端」的硬证据，避免只凭截图像素猜测。
3. **RN 侧对照**：同机启动 `com.deppon.app` 截图 + uiautomator，按同一坐标口径比较尺寸/配色/结构；再按代码定位根因。
4. **门禁验证**：`pnpm verify:app` 系列静态门禁（详见第六节）。

## 七、未决项与风险（需要你确认或下轮补）

1. **增值服务的 3 个生产端条目缺后端契约**：`双人派送`、`通电验机`、`拍照服务（拍照签收 / 取货照片）` 在 RN 下单载荷 `src/services/express/express.payload.ts` 中没有对应字段，生产端包内可见 `验机件数`、`5元/票` 等计费文案但拿不到字段名与取值规则。**本轮没有为了「看起来一致」而伪造这几行**，页面只列 RN 已建模的 5 类服务。要补齐需要抓生产端请求或后端接口文档。
2. **明细里的「优惠信息 -¥1」**：生产端数值来自券抵扣；RN 只有券列表里的 `optimalFee`（分），本轮按「匹配到已选券」才渲染优惠分区，未选券时不显示。若生产端在无券时仍显示 0 元行，需要再对齐。
3. **协议弹层的「历史记录」版本列表**：生产端是内嵌列表（11 条日期链接）；RN 只有 `PROTOCOL_RECORD` H5 页，本轮以「历史版本记录 >」跳 H5 承接，接口级对齐需要后端版本接口。
4. **蒙层动画无法录屏复核**：本机 `screenrecord` 不可用，只能按静态截图 + 生产端 UI 结构推断「蒙层静态、面板滑入」；建议换一台可录屏机型抓 30fps 开场帧确认。
5. **客服拖动边界未量测**：生产端只验证了「可上移且贴边」，上下限没有量到；当前实现钳制在向上 520、向下 40（设计稿 px），需要时可调。
6. **未填地址态尚未在 RN 侧截图对比**：RN 收/寄件人保存时会校验姓名，无法人为造出空态；需要「全新草稿」入口或清缓存后截图复核。
7. **增值服务页的视觉细节**：当前复用 RN 既有服务组件（标题 + 开关 + 字段），生产端是「图标 + ⓘ + 单选圆 + 描述 + 服务费行」。结构已独立成页，但图标/ⓘ/单选圆/服务费行尚未逐项还原，建议作为下一轮的样式收口项。
