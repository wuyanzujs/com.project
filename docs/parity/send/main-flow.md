### 产品卡裁切缺陷与修复

真机首次渲染真实报价时暴露产品卡文字裁切：产品名折行第二行被截断，时效被省略成「运输时效：…」。核实与修复依据：

1. 生产 APK `libapp.so` 的 UTF-16 字符串里没有「运输时效」，但有「惊喜优惠」，说明 RN 卡片上的前缀不是生产端文案。
2. 同体系小程序 `pages/send/express/basic/product/item` 的卡片把时效按 `天/号…前` 拆成前段、时刻（加粗）、后段居中展示；产品名超过 4 字时切换加宽背景图、标题单行（`text-22 leading-none`），短名用 `pl-16`、长名用 `pl-8`。
3. 修复（`ExpressQuoteSection` + `express.quoteView`）：产品名单行、超过 4 字加宽标题带（124→165）、内距按长短名切换；时效改为三段居中展示并去掉前缀；按 `discount.marketCode = XLYHF` 补「惊喜优惠¥X」角标；价格行高度/间距对齐参考端 `h-36 mt-4`。
4. 视图模型新增 `longName`、`timeSegments`、`timeLimit`，并移除随前缀一起失去用途的 `timeValue`；新增 `scripts/business-tests/express/quote-card.test.cjs` 固定拆分规则、角标来源与渲染结果（标题单行、加宽形态、三段时效、无「运输时效」前缀）。

### 协议行常显

生产端寄件页空态就显示「已读并同意《电子运单服务协议》」行（`prod-04.xml`），此前 RN 要等货物与双方地址齐全才渲染。现已改为常显，`useExpressSubmit` 新增 `attempted`，校验文案只在用户点过下单后才展示，避免空态出现校验噪音。

## 契约纠正

1. `preAllocationCourier` 输入 orderNumber，用于下单后调度信息，不是生产下单前 postman tile 的候选列表。
2. `queryGoodsNameList` 输入 standardLevelGoodsNames，用于标准分类，不是热门品名或联想接口。
3. `queryFileUploadInfoBatch` 的真实调用是业务示例图片，不是 Excel 上传；批量导入另查真实契约。
4. `queryMaterialSupply` 在小程序用于火锅物料，不能替代普通纸箱目录或据此推断所有包装库存。
5. `queryIsAgreement` 在小程序为特定地区家电家居协议；不能将它接成全局电子运单已读检查或实名强制门禁。
6. 产品卡时效文案不拼接「运输时效：」，生产端无此字符串，且参考端只展示拆分后的前段/时刻/后段。
7. `discount.marketCode = XLYHF` 是线路限时优惠（产品卡「惊喜优惠」），`YHJ/YHQ` 才是券优惠；两者不能混用。
